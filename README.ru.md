# product-name-classifier

Классификация товаров каталога только по названию, полностью локально.

[English version](README.md)

Задача пришла из логистического проекта: складской каталог примерно на 540 000 строк нужно было
разделить на обувь и всё остальное. Единственным надёжным входом было название товара свободным
текстом, а существующая колонка с метками содержала ошибки. Код здесь общий, класс настраивается, а в
репозитории лежит генератор синтетического каталога, поэтому проект запускается без реальных данных.

## Почему это сложнее поиска по ключевым словам

Список ключевых слов работает неожиданно неплохо, а потом ломается на реальном тексте каталога:

- **Немецкие составные слова.** `Blockabsatz-Sandaletten`, `Schlupfloafer`, `Sockenstiefel`. Для
  модели, работающей по словам, каждое из них это один незнакомый токен.
- **Обрезка.** Система-источник режет каждое название на 40 символах, и информативный хвост часто
  теряется: `Friends Like These Stacked Heel Faux Sue`.
- **Несколько языков в одной колонке.** Немецкий, английский и испанский вперемешку.
- **Ловушки.** Джинсы `Bootcut`, вырез `U-Boot-Ausschnitt` и `Sneakersocken` содержат обувные слова и
  обувью не являются.
- **Битая кодировка.** UTF-8, прочитанный как cp1252, превращает `Mädchen` в `MÃ¤dchen`.
- **Дисбаланс.** К положительному классу относится около 7% уникальных названий.

## Подход

Символьные n-граммы вместо слов: они переживают составные слова, обрезку и опечатки, и им не нужен
словарь под каждый язык.

1. Починить кодировку и свести данные к уникальным названиям. Одно название повторяется в строках
   многократно, поэтому обучение по строкам привело бы к утечке одного и того же названия
   одновременно в обучающую и проверочную часть.
2. `TfidfVectorizer( analyzer="char_wb", ngram_range=( 2, 5 ), min_df=2, sublinear_tf=True )`.
3. `LogisticRegression( C=10, class_weight="balanced" )`. Веса классов важны из-за дисбаланса: иначе
   модели выгодно всегда отвечать «не обувь».
4. Честная оценка через 5-fold stratified cross validation: каждое предсказание делает модель,
   которая это название не видела.
5. Предсказания между 0.2 и 0.8 помечаются как `needs_review`, а не решаются молча.

Скрипт обучения дополнительно печатает самые уверенные расхождения с существующими метками. На
реальном каталоге так нашлись примерно 280 товаров, которые колонка меток относила к «не обуви», хотя
это явно обувь. В этом и состоит практическая польза проекта.

## Приватность

Проект делался для данных, которые не должны покидать компьютер владельца:

- в коде нет ни одного сетевого вызова, всё считается локально;
- реальный каталог и обученная модель никогда не попадают в репозиторий. Модель, обученная на
  настоящих названиях, хранит десятки тысяч символьных фрагментов этих названий, поэтому `*.joblib`
  стоит в `.gitignore` рядом с `*.xlsx`;
- проверяется просто: отключить компьютер от интернета и запустить. Ничего не изменится.

## Быстрый старт

Нужен [uv](https://docs.astral.sh/uv/).

```
uv run make_sample_data.py   # пишет data/products.xlsx, синтетический каталог
uv run train.py              # отчёт cross validation, затем сохраняет model.joblib
uv run classify.py           # пишет "data/products - classified.xlsx"
```

Полезные флаги:

```
uv run train.py --input path/to/catalog.xlsx --examples 10
uv run train.py --test        # первые 20000 строк, модель не перезаписывается
uv run classify.py --output path/to/result.xlsx
```

Чтобы запустить на своём файле, укажи его в `--input` и задай `NAME_COLUMN`, `LABEL_COLUMN`, а если
колонка меток означает обратное, то и `INVERT_LABEL` в начале `train.py`.

## Что на выходе

`classify.py` копирует все исходные колонки и добавляет три:

| Колонка | Значение |
| --- | --- |
| `probability` | уверенность модели, от 0 до 1 |
| `predicted` | 1 или 0 по порогу 0.5 |
| `needs_review` | 1, если вероятность попала в диапазон 0.2-0.8 |

Исходный файл не изменяется.

## Результаты на синтетических данных из репозитория

```
              precision    recall  f1-score   support
    negative      1.000     0.995     0.997       594
    positive      0.995     1.000     0.997       571
    accuracy                          0.997      1165
```

Цифры льстивые, и читать их как оценку качества нельзя. Генератор пока простой: он даёт около 1200
уникальных названий из нескольких шаблонов, после дедупликации классы оказываются почти
сбалансированы, а шума в разметке нет вовсе. В планах распределение повторов по Zipf, дисбаланс на
уровне уникальных названий, намеренно испорченные метки и опечатки. На реальном каталоге метрики
считаются против меток, которые сами содержат ошибки, поэтому список расхождений важнее цифры
accuracy.
